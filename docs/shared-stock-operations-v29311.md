# v293.11 共有商品の手動入出庫

共有商品一覧→商品詳細の入庫・出庫を、操作番号付きAPIへ切り替える。ローカルの通常入出庫・棚卸・販売実績は自動同期しない。共有在庫と端末内の在庫は別系統。ほかの端末では再読み込みする。

## 保存の保証

- UUID操作番号と担当ユーザー・内容ハッシュの一致時のみ保存済みの結果を返す。同じ操作番号は履歴・在庫を再変更しない。
- 未確認操作はアプリのパス別にlocalStorageへ保存。トークンは含めない。ページを読み直しても自動送信せず、ホームの再確認ボタンから同じ操作を送る。
- 未確認操作が残る間は新規操作を止める。同じユーザーのログインが必要。保存領域を使えないときは送信しない。
- 商品と全保管場所をロックし、表示時の場所別在庫全体と厳密比較。変更済みなら409で停止し再取得を促す。
- 数量は1～100万の整数。出庫後の負数は禁止。廃盤の入庫は禁止。既存場所または既定の場所に入庫できる。
- 在庫・入出庫履歴・操作記録はInnoDBの単一トランザクション。履歴失敗時は全ロールバック。
- 保存後の再表示に失敗した場合は「保存済み」と表示し、そのフォームの追加送信を止める。

## 配置順

1. 既存サーバーのDBバックアップを取る。
2. `server/tools/inventory-v29311-setup.php` を `/home/jyuubee/private/`、`server/migrations/004-shared-stock-operations.sql` を同所の `inventory-v29311.sql` として配置。
3. SSHで `php /home/jyuubee/private/inventory-v29311-setup.php migrate`。`operation_table_ready:true` を確認。既存商品の数量は変更しない。
4. `shared-stock-operation-auth.php`, `shared-stock-operation-service.php`, `stock-csv-service.php` を公開inventoryフォルダーへ配置しPHP構文を確認。
5. 隔離した検証用アプリで架空商品だけを入庫→別端末再読込→出庫して元へ戻す。操作後の履歴は残る。
6. 本番アプリの公開はユーザー承認後。旧APIは削除・上書きせず、新API未配置時も旧APIへ自動フォールバックしない。

## 検証

Nodeで入力不正、未確認操作の復元・同一番号再送、アカウント変更、通信失敗、競合、保存済み後の表示失敗を検証。
CIの使い捨てMySQLで入出庫、リプレイ、拒否、ロールバック、二重同時送信・異なる番号の同時競合を検証。本番APIは自動テストで呼ばない。

## 対象範囲

棚卸、販売実績の通常画面からの自動同期、加工・移動、ケース割れ管理は今回の対象外。
