# v293.15 販売実績集計と共有データによる参考判定

全データバックアップの販売実績を商品別・月別にまとめ、通常の取引と月平均から除外する取引の数量を別々に共有します。清水産業・後藤の判定は従来の正規化・除外処理を使います。返品による負数も月別数量に含めます。取引先名、売上明細、商品の在庫数は送信しません。取込期間は日付の範囲だけを共有します。過去の在庫出庫は再実行しません。

## 共有手順

1. サーバーの変更前バックアップを取得する。
2. 非公開フォルダーへ inventory-v29315-setup.php と inventory-v29315.sql を配置し、構文確認後に migrate を実行する。
3. 公開APIフォルダーへ shared-sales-summary-auth.php と shared-sales-summary-service.php を配置し、PHP構文を確認する。既存の shared-planning-service.php と非公開認証処理を利用する。
4. 検証アプリで管理者ログインし、設定の「販売実績の月別集計を初回共有」へ進む。
5. 普段使っているアプリの最新の全データバックアップを選び、件数と対象年月を確認する。検証アプリの空のデータをバックアップしない。
6. 内容を確認後に初回共有する。保存済みの実績集計を別の内容で上書きできない。同じ管理者・内容・操作番号なら保存済みの結果を返す。結果不明時は「前回の実績共有を再確認」を使う。
7. ホームの「共有データで再計算」を押し、参考判定を確認する。既存の端末内の発注・船積み一覧と同じ基準日・在庫・予定条件で比較する。

バックアップの読み込みは100MBまで、月別送信データは4MBまで。月別行は30,000行、取込期間は10,000件まで。日付や数量が不正な実績は行番号を表示して停止する。取込期間の記録がない古いデータは、期間確認済みとして扱わない。

## 判定と表示

- 共有在庫、初回共有した予定、初回共有した月別実績を同じ読み取りトランザクションで取得する。取得失敗・ログアウト・共通データからの切替時は表示を消し、端末内の在庫へ切り替えない。
- 発注は従来の直近6か月の月平均、3か月の見込み、販売予定、季節補正、発注残を使う。専用・廃盤・廃盤予定は従来の除外処理に従う。発注残が不明の商品は0とせず、未判定として別に表示する。
- 船積みは従来のモービック候補、7日前の販売予定一括計上、前年実績補正、先行の確定船便、現在の振分けを使う。入荷済み・確定済みの船便を自動候補から除外する。次便がない場合は判定不可と表示する。
- 実績期間の記録が不足していれば参考値と表示する。共有日時・判定日を明示する。明細は商品コード・商品名で検索できる。登録・入庫・出庫などのボタンは追加しない。

## この版の範囲

月別実績と予定は初回共有時点のスナップショットで、後日のCSV取込や端末内の予定変更は自動同期されません。参考判定として表示し、共有日時を確認してください。実績や予定の継続更新、共有船便の編集・確定・入荷反映、販売明細の閲覧・検索は今後の対応です。日別・取引先別の分析には、この月別集計を売上明細の代わりに使わないでください。

## 検証

架空の原始実績と月別集計を使って、発注の月平均・季節補正と船積みの推奨数が一致することを比較する。計算時に端末内ストレージの取得や移行処理を呼ばないこと、船便計算後に従来画面の状態が戻ることを検証する。権限・プレビュー非保存・再送・上書き拒否・保存失敗のロールバック・商品/在庫/履歴の不変を隔離MySQLで確認する。実データと実件数は公開リポジトリに含めない。
