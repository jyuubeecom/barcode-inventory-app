# v295.2 共有棚卸の確定・在庫反映

管理者が「確定・在庫反映の内容を確認」から、全対象の登録在庫・実在庫・差異と6種類の集計を確認し、確認チェックと最終確認を経て実行します。数量保存・結果確認・取消だけでは現在庫を変更しません。

## 制限と競合

- 全対象の数量保存が必要です。未確認を0個として扱いません。確認済みの0個は反映します。
- 開始時点の対象保管場所の数量と現在庫が一致しない場合は停止します。自動で現在庫へ差異を足したり、別の数量へ置き換えたりしません。
- 確認後に商品・数量・棚卸メモ・保存版・在庫履歴等が変わった場合も停止し、再確認が必要です。
- 開始後からプレビュー前までの在庫の増減が元の数量へ戻っていた場合、その履歴をプレビューに含めて確認時点の在庫に対して確定します。プレビュー後の増減と取消は履歴番号で検出します。
- 対象は開始時のスナップショットです。開始後に追加された別商品は入りません。
- 同じJANの商品も社内コードごとに別々に反映します。対象外の保管場所は変更しません。
- 確定と在庫反映は一体です。「確定だけ」や確定の取消・再編集は今回の対象外です。
- 確定後は作業者・管理者とも閲覧だけです。保存済み一覧に「確定・反映済み」と表示します（新しい順100件）。

## 記録と通信断

差異のある商品のみ、保管場所の数量を実在庫へ更新し、全保管場所合計の変更前後・符号付き差異・担当者・棚卸番号・操作番号を「棚卸調整」の履歴に記録します。差異なしの商品は履歴を増やしません。

棚卸状態・在庫・履歴・反映前の監査記録・操作番号による応答記録を同一トランザクションで保存し、途中失敗は全体をロールバックします。棚卸親行と商品・在庫を固定順序でロックします。確定済み状態と監査テーブルの棚卸番号主キーで二重反映を防止します。

反映操作の番号と確認トークンは送信前にsessionStorageへ保存します。通信断・同じタブの再読み込み後は同じ担当者が「前回の保存を再確認」で同じ内容を再送します。保存領域が使えない・壊れているときは新しい反映を送りません。トークン・パスワードや商品在庫全体は保存しません。タブを閉じた場合はこの再確認情報が失われますが、サーバーの確定状態・履歴・監査記録は残り、同じ棚卸の二重反映は拒否します。
