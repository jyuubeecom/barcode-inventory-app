# v294.0 Amazon準備用とピッキング・パッキング用

管理者が「端末内の従来機能を使う」を選ぶと、ホームの「販売・実績」から「Amazon準備用」と「Amazonピッキング・パッキング用」を開けます。

- C列：配送センター／配送先、E列：JAN（製品コード）、N列：依頼数量／数量。先頭に見出しが必要。
- UTF-8（BOMあり／なし）とShift_JISに対応。文字化けするときは文字コードを選び直す。
- 商品別はJANごとの依頼数量合計、配送先別は配送先合計と配送先・JAN別の内訳。どちらも印刷可能。
- 在庫・販売予定は「この端末」の取得時点のデータ。共有サーバーからの自動取得ではない。
- JANは文字列で照合。8桁／13桁とチェック桁を確認。指数表記、末尾に0が6桁以上続く値は要確認に分ける。後者は丸めの可能性を検知する保守的な確認であり、JANが必ず誤りだという判定ではない。
- 要確認行は商品別集計と在庫照合から除外し、元の行のまま表示。数量を確認できる行は配送先合計には含める。数量不明行は個数の合計に含めず、総数量未確定の表示を出す。
- 同JANの商品が複数ある在庫は、商品単位の総在庫が最大のものを採用。別商品の重複在庫を加算しない。重複のいずれかに在庫数不明があれば最大値を確定せず要確認とする。
- 同JANのいずれかの商品の社内コードに販売予定が登録されていれば黄色と「販売予定あり」。登録済みの全予定（過去分を含む）が対象。予定数量を現在庫から差し引かない。
- 現在庫が全配送先のAmazon必要数より少なければ、現在庫の数値を赤字にし「在庫不足」と不足数を併記。未登録・在庫数不明と0個を区別する。
- 配送先別の在庫欄は全体在庫の参考表示。各配送先への在庫割当・配送先ごとの引当可能数ではない。全配送先必要数も併記し、不足判定は全体需要に対して行う。
- 配送先別では「表示・印刷する配送先」で1件または全件を選択できる。要確認明細と数量合計も選択範囲に絞る。商品別に切り替えるとCSV全体を表示する。在庫不足は絞り込みにかかわらず全配送先の必要数で判定する。
- CSVを読み直すと集計は置き換わる。「現在庫・販売予定を再取得」で端末の最新情報と再照合する。画面を閉じるとCSVを再選択する必要がある。
- 「架空データで試す」は画面内だけのデモ。在庫・予定・CSVの保存やサーバー送信は行わない。

## Amazonピッキング・パッキング用

ホーム → 販売・実績 → Amazonピッキング・パッキング用。Amazonから取得したPickListを選びます。PO・配送センター・ASIN・JAN・モデル番号・商品名・受領待ちのケースを明細ごとに表示します。元の行順とPOごとの明細を保ちます。

配送センターを選ぶと、表示・印刷・作業用CSV・Excelがその配送センターに絞られます。ピッキング確認・パッキング確認の空欄を作業に使えます。数量はPickListの「受領待ちのケース」を使用します。入力に不備がある場合は該当明細を示し、修正後にCSVを読み直します。

「作業用Excelを出力する」で、JANやモデル番号を文字列として保存した .xlsx を開けます。ケース数は数値です。出力CSVはUTF-8 BOM付きです。先頭に0があるJANをExcelで扱う場合は、CSVの取り込み時にJANコード列を文字列として指定します。
