# v295.0 共有棚卸：開始・数量保存

## 対応範囲

共通データのホーム「棚卸を開始・再開」から、棚卸日・保管場所を選び開始する。
ログイン中の管理者・作業者が利用できる。担当者は認証済みのアカウントから記録する。
選択した保管場所に在庫行のある商品（明示的な0個を含む）を対象とし、商品情報と開始時点の在庫をコピーする。
在庫行のない商品を自動的に0個扱いして対象に追加しない。対象商品追加は今回の範囲外。
JANが同じ商品も社内コードで区別する。開始後に現在庫やマスタが変わっても棚卸の記録は変えない。

実在庫・メモを商品ごとに保存し、別のPC・スマホから同じ棚卸を開いて再読み込みできる。
空欄は未確認、0個は確認済みとして区別する。商品名・商品コード・JAN・社内コード検索、確認状況の絞り込み、50件ずつ表示に対応。
一覧は新しい順に最新100件、1棚卸は最大5000商品、保管場所候補は最大300件。

**今回は下書き保存のみ。在庫への反映・棚卸確定・共有棚卸のCSV・カメラ読み取りは未対応。**
従来の端末内棚卸・在庫・履歴は変更しない。共有棚卸は端末内の全データバックアップには含まれない。

## 競合と通信失敗

- 保存時に商品の更新番号を確認し、別端末で更新済みなら409で止める。再読み込み後に確認して入力し直す。
- 開始・保存にはUUIDの操作番号を付け、同じ操作番号・担当者・内容の再送を二重に保存しない。
- 応答不明の間は新規保存を止め「前回の保存を再確認」を表示。401・500・通信失敗は未確認として保持する。
- 未保存入力・未確認操作はページを開いている間だけ保持する。再読み込み・タブ終了前はブラウザの警告を出す。終了を強行した場合はサーバーの棚卸一覧を開き直し、実際の保存結果を確認する。
- ログアウト・アカウント変更で表示中の棚卸を消し、古い応答を画面に反映しない。未確認操作の再送は同じ担当者に限る。
- API応答・認証トークン・棚卸データをService Workerにキャッシュしない。

## サーバー配置（公開前に必要）

1. 既存サーバーのデータベースを通常の方法でバックアップする。
2. `server/migrations/007-shared-stocktaking.sql` を既存の在庫DBに実行する。新規の棚卸用3テーブルだけを追加するSQLで、現在庫・商品マスタ・入出庫履歴を更新しない。既存の同名テーブルがある場合は構成を照合し、削除・再作成しない。
3. 以下の2ファイルを、既存の入出庫APIと同じ `/inventory/` に置く。
   - `server/shared-stocktaking-service.php`
   - `server/shared-stocktaking-auth.php`
4. 共通の `stock-csv-service.php`、既存の非公開DB設定・認証をそのまま使う。設定ファイルや認証ファイルを公開フォルダーへコピーしない。
5. サーバー配置後、フロントを承認済みの公開手順で反映する。GitHub Pagesへの公開だけではPHP・DBは更新されない。

PHP8.1以降・pdo_mysql・mbstring、MySQL8/InnoDBを前提とする。テーブル未準備時は503で案内し、棚卸操作を止める。

## ファイルと配置

新規：`shared-stocktaking.js`（ホーム内の共有棚卸画面と通信）、`server/shared-stocktaking-{service,auth}.php`（認証・開始・保存・取得）、`server/migrations/007-shared-stocktaking.sql`。
既存ファイルへの追加：共通ホームのボタン、作業者メニューの許可、スクリプト読込、キャッシュ更新。既存の棚卸ファイルへの置き換えは不要。
このブランチには完成ファイル全文を保存している。手作業でコードの一部を貼り付ける必要はない。

## 検証

- `node --test tests/*.test.cjs`：数量、未確認と0、通信断再送、別アカウント、誤応答、二重送信、認証変更。
- `php tests/shared-stocktaking-mysql.php`：架空データと `inventory_csv_test` 専用。開始・別アカウント読取・重複JAN・0個・更新競合・入力拒否・在庫不変・在庫変更後のスナップショット・DB途中失敗時の全取り消し。
- 既存の全JSテスト・全MySQLテストを継続。

## 本番での画面確認（サーバー配置後、一つずつ実施）

1. 管理者の共通データでホームを開き、画面版v295.0を確認。
2. 「棚卸を開始・再開」を押す。棚卸日・保管場所・保存済み棚卸一覧が表示される。
3. 架空商品のみのテスト用保管場所がある検証環境で開始。実際の会社の商品を入力・保存するテストは行わない。
4. 実在庫0とメモを保存し、別端末で同じ棚卸を開く。確認済みの0個・担当者・メモが表示される。
5. 同じ商品を両端末で開き、一方で保存してから他方で保存。後の保存は再読み込みを求めて止まる。
6. テスト前後で現在庫と入出庫履歴が同一であることを確認。

エラー時：503はSQL・2ファイル・共通PHPの配置、401は再ログイン、409は別端末更新を確認。応答不明時は同じ操作番号の「前回の保存を再確認」を使う。
