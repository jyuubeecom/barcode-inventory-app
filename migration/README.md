# 既存データを共有サーバーへ移す前の確認

このツールは全データバックアップを端末内で読み取り、移行準備に必要な問題と件数を表示します。既存アプリやデータは修正せず、外部送信、サーバーへの接続、移行SQLの実行はありません。会社の情報を個人サーバーに置く許可を得る前でも、端末内での確認に使えます。

1. 会社で使っている商品データ入りのアプリで「全データをバックアップする」を実行します。v293.5検証用アプリの商品0件のバックアップと取り違えないでください。
2. ZIPをすべて展開し、`inventory-migration-check.html`をChromeで開きます。
3. JSONバックアップを選択します。ファイルはパソコン内で処理します。元ファイルを書き換えません。
4. 商品数・総在庫・履歴件数・確認項目を見ます。「相談用の確認結果」は件数とカテゴリだけで、商品名、コード、得意先名、数量、作成日時を含みません。会社のデータをチャットに添付する必要はありません。
5. 詳しいレポートを保存する場合は社内用に保管します。数量等を含みます。表示を消すと読み込んだ結果を画面から消せます。ブラウザーの永続ストレージへは保存しません。

## 確認する内容と限界

対応バックアップはbackupTypeがbarcode-inventory-app、backupVersionが1～12。商品・履歴等18種の件数、識別番号不足/重複、社内コード形式、サーバーで衝突する可能性のある表記、商品項目の一部の長さ、在庫の非負整数/上限、場所別合計不一致、保管場所の表記、未確認場所、固定状態の引継ぎ、商品マスタに対応しない一部の履歴を確認します。
本社の合算値と各区の棚別在庫が混在するときは、別在庫か合算値かを人が確認する必要があります。勝手に合算・配分しません。ローカルアプリの数量補正関数は意図的に使用しません。
社内コードの表記衝突検査はMySQL utf8mb4_unicode_ciの完全な再現ではなく、保守的な候補抽出です。サーバー側の一意制約による照合が別途必要です。
履歴の全業務項目・ネストした関連付け・外部キーの全検証を保証するツールではありません。エラー0件でも移行承認・完了ではありません。100MBまで、詳細は先頭500件、総件数はそれ以降も加算します。
過去のバックアップ形式では後から増えた項目が無くても警告として扱います。現行形式12で項目が欠ける場合はエラーです。

## 次の移行作業

現在の共有商品CSV取込は新規登録だけで、既存商品の上書き・全履歴の移行を行いません。共有在庫CSVも全データ移行機能ではありません。
実際のバックアップの確認結果をもとに、商品状態（特に専用商品・廃盤予定）、保管場所、既存の共有商品と社内コードの一致を照合し、移行プレビューを作る必要があります。入出庫・棚卸・販売予定・販売実績・船便等は保存先とアプリの読取先も含めて段階的に対応します。
過去の販売実績を新しい売上CSVの「出庫」として取り込むと在庫が再度減ります。履歴の移行と移行後の日々の出庫は、移行開始日時で区切り、同じ在庫を二重に減らさない引継ぎ処理が必要です。
本番移行前には会社の保存先の許可と移行時点のバックアップが必要です。許可がない間はローカル確認にとどめます。テスト商品やテスト取込履歴は本番データに混ぜず、対応方法を別途決めます。

## 開発・再生成

`node --test tests/*.test.cjs`で既存回帰と架空バックアップ検査を実行します。
`python3 migration/build-audit-package.py /absolute/output/inventory-migration-check.zip`で外部ファイル不要のHTMLとこの手順書をZIPにまとめます。標準ライブラリのみを使用します。
実際の会社バックアップ、生成されたレポート、認証情報はリポジトリに保存しません。
